Práctica: Pruebas de Arquitectura Cliente-Servidor mediante Peticiones HTTP GET

1. Explicación del Proceso (¿Qué pasó?)

Se ejecutó con éxito el script 01cliente.js en el entorno de Node.js. Este código actúa en el rol de un Cliente HTTP que inicia un ciclo de comunicación asíncrona. Al inicializarse el proceso, el programa envía una solicitud formal utilizando el método GET hacia la ruta remota /api/talleres expuesta por el servidor backend en la nube.

2. Estado de Conectividad (¿Se conectó o no?)

Sí, la conexión se realizó con total éxito.El programa local resolvió de manera correcta la dirección del servidor remoto y estableció una comunicación segura bajo el protocolo HTTPS (sobre una capa de transporte TCP). El servidor procesó la petición satisfactoriamente, interactuó de manera interna con el servicio de la Base de Datos y devolvió un código de estado de respuesta estructurado 200 OK, completando el ciclo sin interrupciones ni excepciones de seguridad.

3. Elementos Obtenidos

A partir del cuerpo del mensaje de respuesta del servidor web, se decodificaron y extrajeron en la consola local los siguientes elementos:

  • Protocolo y URL resuelta: https://onrender.com
  • Métrica de Rendimiento (RTT): Tiempos de ida y vuelta de los datos que oscilaron entre los 1013 ms y 1119 ms.
  • Status HTTP: Código numérico 200 con el literal interpretado OK.
  • Colección de Datos (JSON Payload):Un arreglo estructurado en formato de texto JSON con tres objetos que corresponden a los talleres registrados en la base de datos:
    • "Introducción a Python" (Instructor: Ing. María López)
    • "Fundamentos de Redes" (Instructor: Ing. Carlos Ramírez)
    • "Diseño de Bases de Datos" (Instructor: Ing. Ana Torres)
